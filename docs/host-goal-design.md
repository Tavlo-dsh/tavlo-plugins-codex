# DSH 目标模式与 Codex 桥接

状态：实现和集成验证完成，尚未发布。前置清理及原生生命周期修复已提交为 `c94d835`。

## 用户入口与状态所有权

沿用 DSH `/goal`、目标模式输入及既有目标栏，不增加客户端组件。DSH `ctx.goals` 是目标身份、版本、轮数上限和续轮授权的来源；只有宿主 `goal-round-driver` 安排下一轮。Codex 原生 Goal 承载当前目标的执行上下文，每个原生回合结束仍自动暂停，防止两个调度器同时续跑。

## 桥接规则

- DSH 已准入的 `source.kind=goal` 消息只有在目标 ID、revision、轮数及 active/armed 状态匹配时才允许转发。继续沿用当前回合归属与消息 ID 去重。
- 原生回合开始前读取宿主目标，创建或同步原生 Goal，并仅为即将提交的一轮启用。相同目标正文只修改状态，保留原生用量。
- 持久记录宿主目标绑定，恢复时读取原生实际状态。完成、阻塞和预算限制通过 `ctx.goals` 的版本检查回传；原生回合结束本身不代表目标完成。旧版本的结果不得覆盖用户编辑后的目标。
- 宿主暂停、清除或编辑已绑定的活动目标时先停止当前原生回合，再同步新状态。由原生终态回传触发的宿主变更不会反过来中断正在收尾的回复。
- 正常回合结束先核对原生 Goal 并回传终态，再暂停原生目标并等待子代理终态，最后让 DSH 结束回合；下一轮由 DSH 自行决定。异常连接失败使相同版本的宿主目标受阻，恢复不会擅自解除限制。
- 宿主目标存在时，`/codex goal` 的修改操作提示使用现有 DSH 目标入口，避免两套命令竞争；查询仍可用。无宿主目标时保留原有独立原生 Goal 命令。

## 预算与恢复

DSH 的轮数上限和 Codex 的 token 预算不等价，不进行数值转换。宿主管理的新目标不继承独立原生目标的旧 token 限制；原生服务返回用量限制时回传受阻，不能通过 DSH 增加轮数自动解除。正文编辑属于目标内容替换，原生目标用量可能重置；DSH 的已用轮数与插件累计 token 统计不重置。

目标创建可先只保存在宿主；原生线程在首次执行时初始化。重启后沿用 DSH 的 disarmed 规则，用户恢复目标后才执行。分叉清除父线程绑定，按新会话的实际宿主目标重新关联。模型切换后旧 Codex 回传不改变其他提供方正在使用的目标。

## 验证

自动测试覆盖已准入续轮消息、过期版本、创建与两轮执行、暂停／编辑／清除竞态、原生完成／阻塞／用量限制、执行和提交失败、普通模式及旧命令兼容。实现保留原有恢复和分叉规则；宿主桥接的完整重启／分叉交互仍随 M6 验收。

`scripts/verify-host-goal.mjs` 已使用真实 DSH 0.2.2-rc.1 的 Goal 服务与续轮驱动、本机 Codex 0.169.0、隔离 Web profile 和 loopback 模型验证：

- DSH 自动准入两轮，目标栏消费的 `goal` 投影与原生 Goal 均为 complete。
- 通过宿主服务暂停活动目标，等待原生暂停，再清除两侧目标与绑定。
- 原生 `update_goal` 报告 blocked 后停止宿主续轮；模型 HTTP 500 回传具体执行失败原因。

全部场景共 6 次本地模型请求、0 次付费模型调用，未使用日常 DSH／Codex home。此验证检查实际服务和投影，没有浏览器点击步骤。复现方式见 [README](../README.md#开发)，结果及剩余边界见 [验证记录](workspace-verification.md)。
