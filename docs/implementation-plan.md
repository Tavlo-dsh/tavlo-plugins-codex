# Codex 原生能力接入计划

创建日期：2026-11-13。状态：M1–M5 后端与命令已逐项实现并通过自动验证；M6 检查与真实文字回合已完成，完整交互、Goal 跨回合和子代理真实生命周期仍待验收。

在现有 App Server 接入基础上，依次完善用量与上下文、Plan 与会话名称、Goal、子代理展示，再完善图片输出与执行过程交互。每项任务的当前状态、验证结果和后续入口维护在 [进度记录](progress.md)；架构背景见 [接入设计](design.md)。

## 已有基础

当前 `0.1.0` 已实现本机 Codex 进程发现与管理、stdio JSON-RPC、原生线程创建与恢复／分叉、输入去重、工具镜像、审批、用户提问、图片输入、取消与辅助模型路由。上一轮已通过 40 项自动测试、类型检查、构建和打包，并使用本机 `codex-cli 0.167.2` 完成未发送模型回合的协议验证。

这些结果是本轮工作的起点。下文已勾选任务对应后续新增的实现与验证；Plan 控制、Goal 有界控制、名称同步和代理命令已实现，完整图形面板与真实交互仍按各阶段的未勾选项跟踪。

M1 实现决策：DSH 0.2.2-rc.1 的标准 usage 同时承担消耗与上下文，无法准确承载原生多次调用；权威统计改由独立 `tavloCodex` 投影及 `/codex usage` 提供，不向标准 usage 写入误导值。详见 [兼容核对](compatibility.md)。未知旧线程恢复及分叉的首个样本标记为 inferred，仅计 last，无法补算首通知前遗漏的多次调用。

## M1 用量与上下文

- [x] **M1.1 核对协议与宿主接口。** 对照已安装 CLI 的稳定与实验协议，整理所需能力、启用方式和兼容回退。核对 DSH 的用量累加、上下文估算及前端状态扩展点。当前工作区只有后端插件，统一 UI 源码位置需在实现界面功能前确认。
- [x] **M1.2 分离用量口径。** 保留 `last` 作为最近一次模型调用快照；依据线程 `total` 的增量记录消耗，在独立投影中按原生回合归集，避免漏算或重复累加。明确缓存读写与推理 token 的包含关系。
- [x] **M1.3 处理统计基线。** 覆盖新线程、恢复、分叉、进程替换、重复／晚到通知、计数回退和执行中排队输入。恢复前的线程累计量不得计入新的 DSH 回合。
- [x] **M1.4 接入上下文事件。** 展示 `contextCompaction` 开始／结束，刷新原生容量与最近用量；处理切换模型和恢复后的状态，明确手动压缩入口。继续由 Codex 管理压缩，避免宿主重复触发。
- [x] **M1.5 验证。** 为多次调用、工具跨步骤、缓存、恢复和压缩场景补充有意义的测试，并核对 DSH 实际使用这些数据的方式。

验收示例：一个原生回合包含三次模型调用，DSH 的消耗记录累计三次，界面上下文使用最近一次可用快照；重复上报同一份累计量不会增加消耗。恢复线程后只记录新增消耗。

## M2 Plan 与会话名称

- [x] **M2.1 定义控制与状态接口。** 为模式、计划步骤和名称定义后端操作与持久状态，接入宿主可用入口；确认统一 UI 的实现位置。实验接口不可用时给出可理解的能力状态。
- [x] **M2.2 接入原生模式。** 按 CLI 支持情况启用实验能力，通过 `collaborationMode` 切换 `plan / default`，保持模型与推理强度一致。模式与 sandbox 分别管理，切换在受支持的回合边界生效。
- [x] **M2.3 展示两类计划。** 将 `turn/plan/updated` 映射为步骤状态；将原生 `plan` item 映射为方案正文，并以完成事件中的最终文本为准，处理最终文本与流式拼接不一致的情况。
- [x] **M2.4 完成计划到执行的交互。** 用户确认执行后，明确切回 Default 再提交执行请求；用户拒绝或取消时保留 Plan 状态。覆盖计划中的用户提问、重启恢复和模型切换。
- [x] **M2.5 同步会话名称。** 对接 `thread/name/set` 与 `thread/name/updated`。以 DSH 用户命名优先；自动标题仅填充未人工命名的会话。避免双向更新循环，并将重命名失败与模型回合失败分开处理。
- [x] **M2.6 验证。** 覆盖进入计划、确认／取消执行、恢复、权限独立性、最终方案修订和名称冲突。

验收示例：只读权限不会被误显示为 Plan；用户确认计划后下轮使用 Default。用户将会话改名后，辅助标题和原生名称通知不会覆盖该名称。

## M3 Goal 生命周期

- [x] **M3.1 建立目标状态模型。** 对接 `thread/goal/set / get / clear` 及更新／清除通知，保存目标、状态、预算、已用 token 和时间。创建与用户操作传递原生接口要求的来源信息。
- [x] **M3.2 恢复与更新目标。** 恢复先读取原生目标；更新状态或预算时保留已有目标的用量。修改目标正文时明确它会替换目标并可能重置计数。
- [x] **M3.3 实现用户操作。** 提供启用、暂停、恢复和清除入口，分别定义“停止本轮”“暂停目标”“结束目标”的行为。仅在用户明确启用时创建目标；预算耗尽不得自行解除限制。
- [ ] **M3.4 验证跨回合运行。** 核对原生目标续跑与 DSH agent 生命周期的配合；区分 `turn/completed` 与目标完成。覆盖等待用户、暂停、受阻、预算限制、断线重启和进程释放，避免无人管理的续跑或重复驱动。
- [x] **M3.5 验证。** 覆盖状态变更、重复通知、恢复不重置用量、预算边界和用户停止行为。

验收示例：目标跨两个原生回合执行后重启 DSH，目标正文、状态和已用预算一致；暂停后不再自行开始新回合。一个回合结束不会被当作目标完成。

M3.4 当前采用有界策略：每个 DSH 回合结束自动暂停原生目标，显式 resume 才继续；未开启原生无人干预连续运行。跨两个真实带认证回合的持续执行与重启验收仍待完成，故保留 M3.4 未勾选。

## M4 子代理状态与面板

- [x] **M4.1 保留原生代理信息。** 适配本机版本的协作调用与 `subAgentActivity`，保存代理 thread id、父子关系、任务、模型、推理强度和状态；记录不同版本的字段差异。
- [x] **M4.2 提供代理列表与详情。** 展示派发、交互、等待、完成、失败和中断；按支持的线程历史接口读取子会话摘要或详情。使用稳定身份更新已有记录。
- [x] **M4.3 明确控制边界。** 由 Codex 原生负责派发；核对可用的补充消息和中断操作后再提供界面入口。手动创建代理属于单独的扩展范围，不通过伪造工具事件实现。
- [ ] **M4.4 处理生命周期。** 核对子代理的订阅、父回合结束后的存活、取消传播、进程退出和重启恢复。审批关联到实际请求者，不能错误附着父工具 callId。
- [x] **M4.5 验证。** 覆盖多个并发子代理、嵌套关系、子代理审批、父子取消以及缺失／晚到事件。

验收示例：两个子代理的状态更新显示为两条稳定记录，子代理审批不会串到另一代理；父会话停止时，已定义的取消行为可观察且无等待泄漏。

M4 后端提供命令列表／详情及已知活跃子代理的 steer／interrupt，实际派发完全由 Codex 原生工具负责；不通过恢复子线程强行订阅事件。图形面板与实际原生并发订阅／重启／父子取消仍待验收，M4.4 保留未勾选。

## M5 图片与执行过程交互

- [x] **M5.1 按模型能力处理输入。** 使用原生 `inputModalities`，避免向文本模型提交图片；保留已有附件完整性与提交前取消语义。
- [x] **M5.2 展示图片输出。** 将图片生成与查看结果接入附件预览；按 CLI 支持区分本地保存路径、直接结果和文件标识，处理不可访问结果及进程退出后的资源生命周期。
- [x] **M5.3 展示工具进度。** 接命令输出增量、MCP progress 和文件补丁更新，保持镜像工具只展示、不执行。覆盖输出截断、取消和最终结果去重。
- [x] **M5.4 接入执行中追加消息。** 提供 `turn/steer` 的受支持入口；清楚区分立即追加和排队下轮，处理活跃 turn 竞争、提交应答和消息去重。
- [x] **M5.5 展示运行诊断。** 处理未登录、额度限制、MCP 启动失败、配置警告和 Windows 沙箱未就绪。只展示与当前操作相关的信息，错误不得被误记为模型正常完成。
- [x] **M5.6 验证。** 覆盖文本模型图片限制、图片预览、长命令增量、最终补丁、steer 竞争及诊断状态。

验收示例：长命令执行期间能看到输出，结束时内容不重复；执行中追加的消息只进入原生线程一次；生成图片可从历史消息中打开。

## M6 真实验收与发布准备

- [x] **M6.1 自动检查。** 按变更执行类型检查、相关测试与构建；发布前跑完整测试和打包检查。保留本机无模型请求的协议 smoke check。
- [ ] **M6.2 DSH 实际交互。** 用已配置的本机 Codex 验证文字／图片、命令／编辑、允许／拒绝／取消、恢复／分叉、命名、Plan、Goal、子代理、上下文和用量。
- [ ] **M6.3 故障验收。** 验证断线、重启、停止超时、原生功能不可用和模型切换失败。确认不会重复执行已提交请求。
- [x] **M6.4 文档与产物。** 更新 README、设计说明、兼容矩阵与进度记录，核对发布包。版本变更按实际完成范围决定；发布是单独动作。

## 进度维护规则

1. 每次继续开发，先读取 [进度记录](progress.md) 的当前状态和下一步，再读取对应阶段的任务。
2. 开始任务时更新任务状态；实现与验收完成后勾选本计划中的任务，并在进度记录追加修改、验证和结果。
3. 进度日志按时间追加，保留历史事实。发现旧结论不成立时新增修正记录，避免覆盖原验证结果。
4. 无真实界面验收的功能标记为“待界面验收”；仅通过协议或模拟事件测试不能将整阶段标记为已完成。
5. 涉及 UI 源码缺失、宿主扩展点或协议限制时，记录具体依赖、已完成部分和下一步，允许继续推进不依赖它的工作。
6. 阶段切换或实现决策变化时，同步更新计划和设计说明；每次交付都在进度记录留下明确的继续入口。
